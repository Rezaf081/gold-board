# خانه‌نو — فروشگاه آزمایشی Django

## اجرا
```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 0.0.0.0:8000
```
دیتابیس همراه پروژه شامل ۸ محصول نمایشی است. تصاویر، تصویرسازی SVG هستند، نه عکس رسمی محصولات. فونت آنلاین اختیاری است و فونت جایگزین دارد.

## تست
```bash
python manage.py test
```
- در «مدیریت فروشگاه» محصول را ویرایش کنید و لینک منبع بدهید.
- `demo://prices` هر بار قیمت را به‌صورت شبیه‌سازی تغییر می‌دهد.
- منابع عمومی مستقیم: JSON مانند `{"price": 12000000}`، فایل CSV یک‌ردیفی با ستون price، یا صفحه HTML دارای itemprop=price یا JSON-LD offers.price.
- واحد منبع را تومان یا ریال انتخاب کنید. قیمت فروش همیشه تومان است.
- به‌روزرسانی دستی، ثبت خطا و زمان آخرین موفقیت پیاده شده؛ زمان‌بندی پس‌زمینه در این نسخه وجود ندارد.
- صفحات جاوااسکریپتی، منابع چندمحصولی و لینک‌های تغییرمسیر نیاز به اتصال اختصاصی دارند. تطبیق سایت واقعی مستلزم بررسی لینک واقعی و مجوز آن سایت است.
- دریافت لینک: منع IP خصوصی، تثبیت IP عمومی، ممنوعیت redirect، محدودیت حجم پاسخ و timeout.

## حدود نسخه نمایشی
پنل مدیریت اکنون نیازمند ورود حساب دارای is_staff است؛ API نیز دسترسی را کنترل می‌کند. ثبت‌نام فقط کاربر عادی می‌سازد. داده‌های واقعی یا حساس وارد نکنید. سبد محلی مرورگر، بدون پرداخت/سفارش/انبار واقعی است. متن خدمات و قیمت‌ها نمایشی هستند.
برای تولید: تقویت محدودیت نرخ درخواست با کش مشترک، بازیابی رمز و تأیید ایمیل، SECRET_KEY محیطی، DEBUG=0، ALLOWED_HOSTS مشخص، HTTPS، پایگاه داده production، صف به‌روزرسانی و زمان‌بندی، تست اتصال منبع و پیاده‌سازی سفارش/موجودی/پرداخت لازم است. این نسخه برای انتشار تجاری آماده نیست.


## حساب‌ها و لینک قیمت — نسخه دوم
- ورود/ثبت‌نام/خروج از بالای صفحه؛ دکمه مدیریت فقط برای مدیر ظاهر می‌شود.
- حفاظت سمت سرور برای ذخیره محصول، به‌روزرسانی قیمت و پیش‌نمایش لینک برقرار است. منابع و گزارش‌ها برای کاربر عادی ارسال نمی‌شوند.
- حساب‌های دمو در دیتابیس همراه پروژه وجود دارند؛ قبل از انتشار عمومی رمز آن‌ها را تغییر دهید یا حذفشان کنید.
- مدیر در ویرایش محصول لینک را خودش تعیین می‌کند. «بررسی لینک و تشخیص قیمت» قیمت را بدون ذخیره نشان می‌دهد؛ دکمه استفاده، قیمت را وارد فرم می‌کند و ذخیره جداگانه لازم است.
- ترب هنوز با لینک واقعی آزمایش نشده و اتصال اختصاصی آن پیاده نشده است. فقط قیمت ساختاریافته یکتا خوانده می‌شود؛ قیمت‌های متعدد و AggregateOffer با خطای روشن رد می‌شوند. استخراج از DOM پویا، انتخاب کمترین فروشنده و دورزدن محدودیت سایت انجام نمی‌شود.
- واحد منبع همچنان انتخاب دستی دارد؛ برای جلوگیری از خطای ده‌برابری بررسی شود.
- محدودیت تلاش ورود/ثبت‌نام از کش محلی استفاده می‌کند؛ برای محیط چندپردازشی کش مشترک و کنترل IP در پراکسی ضروری است.

پیش‌نمایش HTTPS برای کوکی ورود و CSRF از SameSite=None و Secure استفاده می‌کند. برای اجرای محلی روی HTTP متغیر `PREVIEW_HTTPS=0` را تنظیم کنید. اگر مرورگر کوکی شخص ثالث را مسدود کند، پیش‌نمایش را در تب مستقل باز کنید.

## نسخه سوم: مسیر ورود روشن
- دکمه‌های «ورود کاربر / ثبت‌نام» و «ورود ادمین» در هدر، حتی روی موبایل نمایش داده می‌شوند.
- مسیرهای مستقیم `/login/` و `/admin-login/` فرم مربوطه را باز می‌کنند؛ اعتبارسنجی نقش همچنان سمت سرور است.
- فایل‌های CSS و JS نسخه‌گذاری شدند تا کش نسخه قدیمی مزاحم نشود.
- تست مرورگری محلی در عرض ۳۹۰ پیکسل: نمایش دکمه‌ها، ورود ادمین و پنل، خروج و ورود کاربر عادی موفق بود.
- لینک نمونه ترب با شناسه 7dd9d70d-6eaf-4abb-b1be-a1714b61334d با ابزار بررسی وب قابل مشاهده بود، اما دریافت مستقیم از سرور برنامه با timeout مواجه شد. بنابراین اتصال زنده ترب هنوز تأیید نشده و قیمت مشاهده‌شده به‌صورت ثابت در برنامه ثبت نشده است.

## نسخه چهارم: اصلاح ورود در iframe
- لاگ واقعی کاربر: `CSRF cookie not set`، نه رمز عبور اشتباه.
- کوکی‌های session و CSRF در حالت PREVIEW_HTTPS=1 دارای Secure، SameSite=None و Partitioned هستند (CHIPS). میان‌افزار روی پاسخ بیرونی قرار دارد تا کوکی ایجادشده توسط Django را تنظیم کند؛ کوکی حذف‌شده در logout هم همان صفات را دارد.
- CsrfViewMiddleware حذف یا exempt نشده است. کدهای مجزای JSON برای نبود کوکی، توکن نامعتبر و مبدأ نامعتبر وجود دارد.
- صفحات دارای توکن و API ها no-store هستند؛ پیش از ورود وضعیت و توکن تازه دریافت می‌شود. فقط خطای توکن نامعتبر، یک بار با توکن تازه تکرار می‌شود.
- اگر مرورگر کوکی را نپذیرد، فرم لینک ورود در تب مستقل نشان می‌دهد؛ نیازی به غیرفعال‌کردن تنظیمات امنیت مرورگر نیست. نشست iframe و تب مستقل ممکن است به دلیل partition متفاوت، مستقل باشند.
- تست‌ها: ۱۹ تست Django موفق؛ تست Chromium با TLS واقعی محلی، iframe از دامنه متفاوت و محدودیت third-party cookies موفق. وجود partitionKey کوکی نشست بررسی شد؛ ورود، حفظ نشست پس از reload، خروج و رد POST بدون CSRF تأیید شد. این تست شبیه‌سازی محیط پیش‌نمایش است، نه اجرای مستقیم در مرورگر کاربر.
- برای استقرار عادی روی دامنه خودتان، تنظیمات cookie/host/origin را متناسب با آن محیط تنظیم کنید. برای توسعه HTTP محلی PREVIEW_HTTPS=0 لازم است.

## نسخه پنجم: fallback بدون کوکی برای پیش‌نمایش
وقتی دو بررسی متوالی نشان دهد کوکی برنمی‌گردد، frontend خودکار وارد حالت نشست پیش‌نمایش می‌شود. توکن ۲۵۶بیتی تصادفی فقط در حافظه JS نگهداری می‌شود؛ در URL، localStorage یا sessionStorage قرار نمی‌گیرد. سرور فقط SHA-256 توکن را ذخیره می‌کند. توکن مهمان ۱۰ دقیقه و توکن احراز هویت‌شده ۶۰ دقیقه اعتبار دارد؛ ورود و خروج توکن را عوض و قبلی را حذف می‌کنند. تغییر رمز یا غیرفعال‌کردن کاربر هم اعتبار نشست را باطل می‌کند.

این مسیر از هدر صریح X-Preview-Token استفاده می‌کند و هیچ مجوزی از کوکی به آن ارث نمی‌رسد. حساب همچنان با authenticate جنگو بررسی و مجوزهای مدیر در API اعمال می‌شود. فرم cross-origin نمی‌تواند این هدر را ارسال کند و CORS اجازه داده نشده است. بررسی CSRF کوکی فقط برای درخواست دارای توکن معتبر روی APIهای مشخص با احراز هویت مستقل توکنی جایگزین می‌شود؛ سایر درخواست‌ها همچنان به CSRF استاندارد نیاز دارند. نوشتن در حالت توکن فقط JSON است.

با رفرش یا بستن صفحه باید دوباره وارد شد. نشست fallback در دیتابیس ذخیره می‌شود و با restart سرور از بین نمی‌رود، اما توکن در حافظه مرورگر با reload از دست می‌رود. این روش نیاز به حفاظت در برابر XSS و HTTPS دارد؛ برای استقرار واقعی، بازبینی امنیت، CSP، کش مشترک rate-limit و تنظیم دامنه ضروری است.

تست نسخه پنجم: ۲۴ تست Django موفق؛ تست مرورگری HTTPS در iframe با حذف کامل Cookie و Set-Cookie موفق: ورود ادمین، خواندن API خصوصی، خروج، ورود کاربر، رد نوشتن مدیریتی برای کاربر، و صفر بودن کوکی‌های مرورگر. تست ورود عادی مبتنی بر کوکی نیز موفق بود.

## تشخیص خطای نوتریکالا
دریافت مستقیم لینک نمونه نوتریکالا از محیط اجرای فروشگاه در handshake TLS با timeout مواجه شد؛ ابزار مستقل بررسی وب صفحه را نمایش داد. این دو مسیر شبکه یکی نیستند. اتصال زنده این منبع هنوز برقرار نشده است و قیمت مشاهده‌شده در کد ثابت نشده است.
خطاهای timeout، DNS، TLS، HTTP، redirect و تفسیر متن اکنون جدا هستند. URL فارسی و HTML entity مانند &amp; پیش از درخواست normalize می‌شوند؛ این اصلاح به‌تنهایی مشکل شبکه را حل نمی‌کند. ۲۷ تست موفق، از جمله حفظ قیمت قبلی در خطای شبکه.

## نسخه ششم: موتور استخراج قیمت و فایل ذخیره‌شده
در مدیریت فروشگاه → ویرایش محصول → «استخراج و بررسی قیمت»، دو مسیر وجود دارد:
1. دریافت از لینک عمومی قابل دسترس.
2. انتخاب فایل HTML/HTM/JSON/CSV ذخیره‌شده (حداکثر ۱ مگابایت). متن در JSON به API ادمین ارسال و فقط با BeautifulSoup/JSON/CSV تحلیل می‌شود؛ HTML در صفحه اجرا یا روی دیسک ذخیره نمی‌شود و منابع خارجی آن دریافت نمی‌شوند.

خروجی شامل نام محصول در صورت وجود، قیمت تومان، واحد منبع، روش استخراج و هشدارهاست. «تأیید و قرار دادن قیمت در فرم» فقط فرم را پر می‌کند؛ «ذخیره محصول» مرحله جداگانه است. قیمت یا منبع محصولات موجود بدون تأیید تغییر نمی‌کند.

موتور `shop/extraction.py`:
- JSON با price و priceCurrency، Product/Offer در JSON-LD و @graph، متادیتای HTML؛
- قیمت بخش summary / entry-summary ووکامرس با اولویت قیمت ins و نادیده‌گرفتن del و محصولات مرتبط؛
- CSV تک‌ردیفی با ستون‌های name,price,currency؛
- اعداد فارسی و عربی، تبدیل ریال به تومان؛
- واحد صریح منبع اولویت دارد و در تعارض با انتخاب دستی هشدار داده می‌شود؛ حالت auto در نبود واحد خطا می‌دهد؛
- چند محصول، قیمت‌های متفاوت، AggregateOffer/بازه قیمت و ناموجودی اعلام‌شده در پیشنهاد ساختاریافته رد می‌شوند؛ حدس از کل اعداد صفحه انجام نمی‌شود.

فایل `static/sample-product.html` صرفاً ساختگی و برای تست است و به نوتریکالا تعلق ندارد. نمونه داخل پنل قابل دانلود است. استخراج از HTML واقعی نوتریکالا هنوز تأیید نشده چون فایل آن دریافت نشده و اتصال مستقیم timeout می‌شود. این نسخه مشکل شبکه یا صفحات صرفاً جاوااسکریپتی را حل نمی‌کند. زمان‌بندی خودکار هم هنوز اضافه نشده است.

تست: ۴۲ تست Django موفق؛ تست مرورگری بارگذاری HTML، تشخیص قیمت تخفیف‌خورده، رد اثر قیمت محصول مرتبط و عدم تغییر فرم قبل از تأیید موفق بود. در تست مرورگر هیچ محصول واقعی ذخیره یا تغییر داده نشد.
